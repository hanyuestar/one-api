## B. alibailian DoResponse 逻辑审查

修复后代码位于 `relay/adaptor/alibailian/adaptor.go:66-83`。逐分支核对：

| # | 验收项 | 结果 | 证据 |
| --- | --- | --- | --- |
| B1 | 生图分支走 `ali.ImageHandler` | **PASS** | adaptor.go:67-70：`if meta.Mode == relaymode.ImagesGenerations { err, _ = ali.ImageHandler(c, resp); return }`。签名匹配 `ali/image.go:19` `func ImageHandler(c, resp) (*ErrorWithStatusCode, *Usage)`，diff 中该分支未被改动 |
| B2 | 流式分支 `StreamHandler` + `ResponseText2Usage` 兜底 | **PASS** | adaptor.go:73-78：`err, responseText, usage = openai.StreamHandler(c, resp, meta.Mode)`；`if usage == nil \|\| usage.TotalTokens == 0 { usage = openai.ResponseText2Usage(responseText, meta.ActualModelName, meta.PromptTokens) }`。`ResponseText2Usage` 实现于 `openai/helper.go:11`，按 `CountTokenText` 估算 completion tokens，逻辑正确 |
| B3 | 非流式走 `openai.Handler` | **PASS** | adaptor.go:80：`err, usage = openai.Handler(c, resp, meta.PromptTokens, meta.ActualModelName)` |
| B4 | 与 doubao 渠道行为一致性 | **PASS（有轻微差异，见下）** | doubao 无独立 `DoResponse`，走 openai 兼容适配器（`openai/adaptor.go:54-55` 复用 `doubao.GetRequestURL`）。修复后 alibailian 与 `openai.Adaptor.DoResponse`（`openai/adaptor.go:106-126`）逻辑基本一致 |
| B5 | Handler/StreamHandler 签名匹配 | **PASS** | `openai/main.go:27` `StreamHandler(c, resp, relayMode int) (*ErrorWithStatusCode, string, *Usage)`；`openai/main.go:99` `Handler(c, resp, promptTokens int, modelName string) (*ErrorWithStatusCode, *Usage)`。与调用处实参、返回值赋值一一对应 |

**修复正确性专项核验**：
- **原 bug 确认**：`postConsumeQuota`（`relay/controller/helper.go:99`）在 `usage == nil` 时直接 `logger.Error("usage is nil")` 并 `return`，不扣费、不写消费日志。原 DoResponse 非流式解析出 usage 却 `return nil, nil`、流式直接透传不解析 usage，正是返回 nil 的根因。修复后两条路径均返回有效 usage ✅
- **nil 安全分析**：`openai.Handler` 使用的 `SlimTextResponse`（`openai/model.go:79`）内嵌值类型 `model.Usage` 与 `model.Error`（非指针），即使 JSON 字段缺失也只为零值，不存在 `textResponse.Error.Type` / `textResponse.Usage.TotalTokens` 的 nil 指针解引用风险 ✅
- **流式行为**：`openai.StreamHandler` 以 SSE 格式透传并提取 usage，与修复前直接透传 SSE 的客户端兼容性一致 ✅

**B 项差异（观察项，非阻断）**：
- `openai.Adaptor.DoResponse` 流式分支在兜底之后还有一步补全（`openai/adaptor.go:113-116`）：当 `usage.TotalTokens != 0 && usage.PromptTokens == 0` 时回填 `PromptTokens = meta.PromptTokens`、`CompletionTokens = TotalTokens - PromptTokens`。alibailian 修复后的实现未包含此步。当上游流式响应仅返回 `total_tokens` 时，alibailian 的 usage 明细不完整（但不影响以 total 计的扣费总量）。建议后续对齐，**不影响本次验收结论**。
